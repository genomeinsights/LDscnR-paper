# NEMO — background selection with a detectable signature

`bgs2` produced no measurable background selection. `delet_loci 200` ×
`delet_mutation_rate 2e-7` gives U = 4e-5 diploid per chromosome, and the DFE median
h·s = 4e-5 sits *at* the drift barrier 1/(2N), so only ~55% of deleterious loci are
effectively selected at all. Predicted mean B = 0.997 and a 1.3% low-vs-high
recombination π contrast — below the ~5% bar set by π's 4.5% per-window CV.

This folder holds the re-parameterised simulations, ready to run on a cluster.

## Layout

```
R/bgs_predict.R          parameter scan: which settings give a resolvable contrast
R/extend_delet_map.R     how params_V4 was built from params_V3 (provenance; run once)
R/make_run.R             writes run/ini/*.ini and the two manifests
R/make_grid.R            one-replicate parameter grid (chr8, V2_c1, one env)
ini/*.ini.tmpl           burn-in and adapt templates
params_V4/               maps, dispersal matrices, environments  (226 MB, NOT in git)
setup_machine.sh         prepare a fresh machine; --build-nemo clones/patches/builds
nemo-macos-bigpop.patch  the macOS Nemo fix, against nemo-release d3e321b
cluster/submit.sh        submit both stages to SLURM with the dependency wired
cluster/*.sbatch         one array task per run
run_pool.sh              local worker pool (RAM-sized) for run/ or grid/
run_local.sh             short smoke test
PATCHES.md               why the Nemo patch is needed
```

## Why these parameters

BGS strength is set by deleterious mutational input **per Morgan** — B = exp(−2μ) —
not by *s*. Raising *s* alone changes nothing. Two further conditions must hold:
h·s must clear the drift barrier, and the BGS reach (h·s in Morgans) must exceed the
spacing between deleterious loci, or the landscape is a set of narrow spikes whose
depth depends on which loci happened to draw a small *s*. That is why the fix is more
loci, not only a higher rate.

|  | bgs2 (params_V3) | here (params_V4) |
|---|---|---|
| `delet_loci` | 200 (100/chr) | **2000 (1000/chr)** |
| `delet_mutation_rate` | 2e-7 | **1.5e-5** |
| DFE | lognormal(−9.425, 3.36) | **lognormal(−4.6, 1.5)** |
| `delet_dominance_mean` | 0.5 | 0.5 |
| U per chromosome (diploid) | 4e-5 | **0.030** |
| median h·s vs drift barrier | 1× | **185×** |
| BGS reach (h·s) | ~0 | **0.50 cM** |

`Rscript R/bgs_predict.R` reproduces the scan behind that choice (π contrast realised
at 10,000 generations, over all 10 maps):

| setting | load | mean B | mean π | Q1/Q5 contrast |
|---|---|---|---|---|
| 100 loci, u 3e-5 | 1.2% | 0.854 | 0.958 | 16.0% |
| 1000 loci, u 5e-6 | 2.0% | 0.835 | 0.966 | 10.6% |
| **1000 loci, u 1.5e-5** ← chosen | **5.8%** | **0.650** | **0.871** | **43.0%** |
| 1000 loci, u 3e-5 | 11.3% | 0.495 | 0.761 | 71.4% |
| 1000 loci, tight DFE (sd 0.75) | 5.8% | 0.681 | 0.911 | 24.3% |
| 1000 loci, broad DFE (sd 2.5) | 5.8% | 0.627 | 0.830 | 60.3% |

Equilibrium B for the chosen setting is 0.650 with a 72.6% contrast, but the runs are
**mutation-limited, not at equilibrium**: `ntrl_init_model 0` is monomorphic
(`ttneutralgenes_bitstring.cc:74`) and the burn-in is ~0.5 Ne, so H ≈ 2ut and is
largely insensitive to Ne. The realised figures above apply
`H_bgs/H_nobgs = B(1−e^(−t/2NeB)) / (1−e^(−t/2Ne))`. They are conservative: Ne is
taken as census, and a smaller true Ne moves the runs toward equilibrium.

Strength varies ~3× among chromosome sets, tracking their Nemo map lengths
(chr5, 16 cM → B 0.51; chr4, 63 cM → B 0.77).

## What was changed, and what was not

`params_V4` adds 900 deleterious loci per chromosome, drawn uniformly in **physical**
space and avoiding every position already on the map — the same rule
`recombination_map_with_LRR.R` used. Uniform-in-bp is what makes low-recombination
regions absorb more mutations per Morgan, and it is the entire source of the
BGS/recombination correlation.

`map_ntrl*.txt`, `map_QTN*.txt` and `allelic_values_*.txt` are copied **byte-for-byte**
from params_V3. The `nobgs` arm declares no deleterious trait, so it sees exactly the
map it saw before, and the two arms differ only in the deleterious block. They also
share a random seed per (chr, V, c, env). That is what makes
`B_obs = π_bgs / π_nobgs` a matched-pair contrast.

Nemo recombines over `pos_nemo × 3.3e-5` = **53.1 cM per chromosome**, half the 107.7 cM
in the rds `cM` column. This is deliberate (confirmed with PK) — but compute μ per
Morgan in Nemo's units, not the rds column, or you halve the predicted effect.

## Moving to another machine

`params_V4/` is **not in git** (226 MB), so a clone is not enough — copy the folder
across, or copy just `params_V4/` on top of a clone. Simulation outputs (`run/`,
`grid/`) are not in git either, and are regenerated by the scripts.

```bash
rsync -av --exclude 'run/' --exclude 'grid/' \
      ~/gitlab/LDscnR-paper/NEMO/ user@host:~/NEMO/
```

Then on the target machine:

```bash
cd ~/NEMO
./setup_machine.sh --build-nemo    # clone Nemo, apply the patch, build, install
./setup_machine.sh                 # re-check; also reports the worker count
```

`setup_machine.sh` verifies Nemo's version, that the binary-loader patch is present,
R and `data.table`, that `params_V4/` arrived complete, and how many workers the RAM
allows. It refuses to say "ready" if anything is missing rather than letting the run
fail hours in.

`nemo-macos-bigpop.patch` is the fix described in `PATCHES.md`, exported against
nemo-release `d3e321b` and verified to apply cleanly to a fresh checkout. **It is
required on macOS** — without it every adapt run fails on a 4.6 GB `source_pop`.
Applying it on Linux is harmless but unnecessary.

Order of work: run the parameter grid first (12 tasks, ~2.5 h at 3 workers) and look
at which settings separate before committing to the 660-run production set.

## Running it

Scope defaults to the reduced 3 cells the analysis pipeline uses
(`V0.5_c2,V1_c1.5,V2_c1`) × 10 chr × 10 env × 2 arms = 60 burn-ins + 600 adapt runs.
Override with `BGS_CELLS`, `BGS_CHRS`, `BGS_ENVS`, `BGS_ARMS`, `BGS_BURNIN_GENS`.

```bash
Rscript R/make_run.R                          # regenerate run/ini + manifests
./run_local.sh 20                             # optional smoke test
ACCOUNT=project_2003847 cluster/submit.sh     # burn-ins, then adapt held on them
```

Both stages skip any task whose output already exists, so resubmitting after a
partial failure only redoes what is missing.

**Resources.** Nemo is single-threaded: one core per task. The real constraint is
memory — a 2304 × 8 metapopulation with 1e6 bitstring neutral loci holds **~10 GB
resident**, in the burn-in and the adapt phase alike (the loader's read buffer becomes
the population storage). The sbatch files request 14G.

Timing, measured on Apple M3 Pro by differencing runs rather than reading a single
total: **0.265 s per generation** and **12.6 s per stat write** (1200 generations took
362 s with one stat and 501 s with twelve). A 10,000-generation burn-in with
`stat_log_time 500` is therefore ~49 min, and an adapt run ~8 min including the source
load and genotype write — about **130 core-hours for the full 660 runs**. Beware
estimating this from a short run's total: setup and the first stat write dominate
there and inflate the apparent per-generation cost several-fold.

Stored populations are ~99% zero bits and compress to ~100 MB, so disk is not a
constraint.

The adapt array is held on the *whole* burn-in array. An adapt job only needs its own
cell, but SLURM's element-wise `aftercorr` cannot map a 60-task array onto a 600-task
one, so the last burn-in gates the first adapt. Simple, and it cannot race.

**Nemo version.** Run both arms on one binary, ≥ 2.4.2. The existing `nobgs` set used
v2.4.1, which carries the `RandBool()` defect fixed in 2.4.2, while `bgs2` used v2.4.3;
mixing them puts a version difference in the numerator and denominator of every B_obs.
On Linux stock 2.4.2 is fine. On macOS it needs the patch in `PATCHES.md`.

## Measuring the signature — the MAF problem, and the fix

The bitstring neutral trait registers **no file handlers** — `ntrl_save_freq` and
`ntrl_save_genotype` exist only for the byte encoding. The multi-trait genotyper is
the only per-locus output, and `bgs2` ran it with `files_genotyper_trim_maf 0.01`.

That threshold is a problem. Under BGS a low-recombination window loses both
segregating sites *and* allele frequency, so fewer of its loci clear the cut — and
**mean heterozygosity among the survivors is biased upward exactly where the effect is
strongest**. Measuring BGS as mean He over retained SNPs would understate it.

**The fix is `files_genotyper_trim_maf 0`, which is now the default here.** Despite the
warning Nemo prints —

```
WARNING::Genotyper::value 0.000000 for option "files_genotyper_trim_maf" cannot be used
for trimming di-allelic loci.
```

— which is harmless, this keeps every **segregating** site and drops only monomorphic
ones. The filter is `p > _trim_maf && p < 1 - _trim_maf` (`servicenotifiers.cc:587`),
so 0 reduces to "polymorphic". Measured on one run: 10,938 markers at 0 versus 3,258 at
0.01, of which 443 vs 130 are deleterious loci.

Saving genuinely *all* loci is unnecessary. Monomorphic sites contribute nothing to
Σ2pq, and the denominator for per-window π — the total number of sites in the window —
comes from the map in `params_V4/rds`, not from the genotypes.

Note that `p` is the **whole-population** frequency over all 2304 patches
(`servicenotifiers.cc:518` takes the full population pointer), not the frequency in the
80 sampled patches.

**Cost.** About 3.4× the markers, so ~175 MB per run instead of ~52 MB, and roughly
10 GB compressed across 600 runs. That multiplier was measured on a short run; the
site-frequency spectrum shifts as diversity accumulates, so expect it to grow somewhat
over a full 10,000-generation burn-in. Set `BGS_TRIM_MAF=0.01` to reproduce the bgs2
output exactly.

Nothing downstream breaks: the analysis pipeline already applies its own MAF filter
after subsampling, so it will cut these files back to its usual marker set. Do not feed
the unfiltered set to `compute_LD_decay` — its 7.3 GB/process is tuned for ~80k markers.

With unbiased per-window π available, `B_obs = π_bgs/π_nobgs` on the shared window grid
is directly comparable to the predicted B. Keep **SNP density per window** as a second
read: it is more sensitive to Ne than π in this mutation-limited regime, and the paired
form differences away the QTN-clustered marker density (CV 0.57 across 500 kb windows)
that confounds any within-run measure.

Related traps already established: the Chr1-vs-Chr2 contrast is **not** a BGS contrast
(both carry the same deleterious loci; only QTN count differs), and within-run
π-vs-deleterious-proximity is confounded — a nobgs run with no deleterious selection at
all still gave +0.33.
